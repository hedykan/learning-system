## 真实 Agent 复验（2026-09-28，Codex gpt-5.6-sol 低思考，开启网页搜索与网络，9 轮）

**场景 1：只给目标**（“把公司的几个 Java 服务迁到 K8s 上”）

| 轮 | 结果 |
| --- | --- |
| 1 | 用 `--goal` 建课后立即开入学摸底（standard），第一问是“迁移完成后希望独立做到什么程度” |
| 2–3 | 目标访谈：场景、已有基础（Spring Boot、Docker）、时间（每周 4 小时、两个月）、关注点；再问典型服务的依赖与现有发布方式 |
| 4 | 诊断题暴露“所有健康检查失败都会重启”的混淆；结束摸底写入目标卡（4 个关注点）；草拟 8 节课程：Docker 只快速复习、不讲集群搭建、把探针的混淆写进第 5 节；评审全部覆盖，`ready_to_confirm` 为 true |
| 5 | 按学习者要求把“配置与密钥”提前到第 2 节后确认；抓取 7 份 Kubernetes 与 Jenkins 官方文档快照，8 节全部挂上资料，每份都有 `--why` 与 `--serves` |

**场景 2：目标 + 教材**（《Pro Git》EPUB，“在团队里熟练用分支协作、处理冲突、整理历史”，基础操作天天在用）

| 轮 | 结果 |
| --- | --- |
| 1 | 选择跟随教材，并说明基础操作会快速验证后跳过；先问摸底强度 |
| 2–3 | 快速摸底：团队流程、时间，两道诊断题（同步 main 并整理提交、合并与变基冲突） |
| 4 | 第一次结束摸底因摘录的原话与原文不符被拒，Agent 更正后成功；目标卡 3 个关注点；草案按原书顺序选出 8 个相关小节并声明概念；评审的 `likely_known` 为 2、4（合并冲突、远程分支），提示中 rebase、强推为先修缺口；Agent 据此安排这两节快速检验、练习集中在 rebase 与改写历史 |

遗留观察：

- 场景 2 中 Agent 在草案阶段直接只保留 8 个相关小节（仍按原书顺序，待学习者确认），而不是保留全书目录再对不相关章节提出 `skip` 建议；两种做法都经学习者确认，前者目录更短，但失去“全书还有哪些没学”的视图。
- 场景 1 诊断出的“探针混淆”在评估中只记为已有知识，没有标为可能的误解，所以证据提示里看不到它。
