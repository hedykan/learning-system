# 变更摘要

学习对话中，Agent 将 `learn` 的常规记录操作保持在后台，不再反复播报“继续用 Learning OS 记录课程”。

## 动机

Runtime 记录属于实现机制，不是课程内容。反复说明 start、append、status、position 等内部操作会打断学习者思路，并让教学对话显得机械。

## 当前行为

- Session workflow 要求在结束时报告保存的 Session 和 Curriculum Position。
- Agent 容易把工具透明度泛化为每轮学习前的操作播报。
- 学习者看到内部产品名和记录动作，而不是连续的教学回应。

## 目标行为

- 正常查询、启动、追加回合、更新位置和结束会话均在后台静默完成。
- 学习者可见回复直接承接其答案、提出下一个问题或给出必要解释。
- 宿主要求工具调用前提供进度消息时，消息聚焦学习内容或下一教学动作，不描述后台记账。
- 只有操作失败、需要用户选择、需要确认潜在覆盖/删除、或用户主动询问记录状态时，才说明 Runtime 行为。
- Session 结束时总结学习内容与下一步，不默认报告内部文件、命令或产品名。

## 数据与兼容性影响

不改变 CLI、Schema 或已有数据，只更新内嵌 Agent Skill。旧 Vault 通过 `learn agent update` 安全升级。

## 风险

静默不等于隐藏错误或需要授权的操作。所有阻塞、失败和重要确认仍须明确告知用户。

## 验收条件

1. Skill 明确要求常规 Runtime 操作保持后台静默。
2. 学习中的普通回复不包含工具执行播报。
3. 失败、确认和用户主动查询仍得到明确说明。
4. Session 结束默认输出学习总结和下一步，而非内部保存路径。

## 决策

作为 v0.1.1 的教学体验验收缺口立即修正。
