# 变更摘要

每张概念笔记增加一段“教材要点”：Agent 读过原书对应页后，用几句话概括原书对这个概念的讲法，并注明页码。它与学习者原话、AI 对学习者的解释分区展示。

## 动机

v0.1.3 实测生成的概念笔记只记录学习者如何理解、哪里变化、依据是什么，不包含原书讲了什么。学习者在 Obsidian 中复习时，缺少对照原书的锚点。

## 与既有原则的关系

`learner-model.md` 的非目标“生成教材百科摘要”继续有效：本变更只允许每个概念几句话的要点，不生成章节摘要或全书笔记；要点必须来自读过的原文页，不能来自模型记忆。

## 目标行为

- Interpretation Record 的 `concepts[]` 可带可选字段 `textbook_points`：

  ```json
  {"id": "tail-latency", "label": "尾延迟",
   "textbook_points": {"pages": [34, 36], "points": ["响应时间是分布而不是单个数字", "高百分位数（如 p99）决定最慢用户的体验"]}}
  ```

- 校验：`points` 1 到 5 条，每条 4 到 120 个字符；`pages` 为 `[start, end]`；目录已确认且 Concept 有 node 时，页码必须落在该条目的页码范围内（条目无页码则只校验格式）。
- 同一 Concept 再次提交要点时，新版本取代旧版本；旧版本保留在修订历史中。
- 投影在概念笔记“教材来源”之后新增“## 教材要点”，标注“AI 根据原书第 X–Y 页概括，未经学习者核对”；学习者原话、AI 对学习者的解释仍各自分区。
- Skill 规定：只在读过对应页之后写要点；未读原文时省略该字段；要点用原书的术语，不加入书中没有的内容。

## 数据与兼容性影响

Interpretation Record schema 保持 `@1`，`textbook_points` 为可选新增字段；旧记录与旧投影不受影响。

## 风险

- Runtime 无法核对要点是否忠于原文，只能校验页码范围与长度；投影明确标注来源与“未经核对”。
- 要点可能被误认为学习者已经掌握；它放在单独分区，并且不影响概念状态。

## 验收条件

1. 带合法 `textbook_points` 的记录被接受，概念笔记出现“教材要点”并注明页码。
2. 页码超出目录条目范围、条数或长度越界的要点被拒绝且零写入。
3. 再次提交要点后笔记显示新版本，修订历史保留旧版本。
4. 没有要点的概念笔记不出现空的“教材要点”分区。
5. Agent 实测：讲过一节后提交的要点与原书该页内容一致，且没有在未读原文时提交要点。

## 决策

2026-09-26 接受，进入 v0.1.4。
