# 变更摘要

把本地 Git 代码项目作为资料导入，按提交号固定版本；目录由 Agent 按模块或调用链建立，定位为“文件#行号”。落实 IDEA-007 的初步边界。

## 目标行为

- `learn source add <仓库路径> --kind code`：默认 link，不复制仓库；记录本地路径、提交号、分支和是否有未提交修改（有未提交修改时警告，版本仍以提交号为准）。
- 能力：`Structured: false, Extractable: true`。`source read <资料> src/raft.go#L120-180` 用 `git show <提交号>:<路径>` 读取，不受工作区后续修改影响。
- 读取与索引时排除 `.git`、构建产物、依赖目录（`node_modules`、`vendor` 等）、二进制文件，以及凭据类文件（`.env`、`*.pem`、`id_*`、`*.key` 等），命中时返回拒绝原因。
- 项目有新提交时，`learn source add` 同一路径生成新版本；学习者选择继续旧版本或迁移到新版本，旧记录的定位始终指向旧提交。
- Skill：代码学习以预测为主（“这个函数会被谁调用？”“改掉这一行会发生什么？”），迁移证据可以是学习者在另一个模块里认出同样的设计。

## 数据与兼容性影响

纯新增。Vault 只保存元数据，不保存代码。

## 风险

- 大型仓库性能：只按需读单个文件，不预先建索引；验收用一个超过一万个文件的仓库。
- 凭据泄露进学习记录：排除规则由程序强制，不依赖 Agent 自觉。

## 验收条件

1. 导入后修改工作区文件，`source read` 仍返回导入时提交的内容。
2. 读取 `.env` 等凭据文件被拒绝。
3. 超过一万个文件的仓库导入与读取在 2 秒内完成。
4. 新提交后生成新版本，旧记录定位仍可读取。

## 决策

2026-09-28 接受，排入 v0.1.8；同日随版本拆分移至 v0.1.9。
