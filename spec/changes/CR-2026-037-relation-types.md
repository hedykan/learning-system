# 变更摘要

`related` 增加可选的 `type`：先修、易混、组成、应用、其他。有方向的关系只在一端写双链，使 Obsidian 图谱上的箭头有意义；关系兜底从“至少连一个”改为“明确回答连不连，宁缺毋滥”。跨教材的关系单独突出。

## 动机

Obsidian 的边没有类型，只能靠方向和节点颜色区分。现在所有关系都是无类型、双向的；兜底规则让 Agent 为了结束学习可能凑出弱连接，弄脏图谱。先修关系也是 v0.2 课程排序需要的数据。

## 目标行为

| type | 方向 | 例子 | 双链写在 |
| --- | --- | --- | --- |
| `prerequisite` | A 依赖 B | 复制延迟 → 复制 | A |
| `part_of` | 部分 → 整体 | ETag → 缓存验证 | 部分 |
| `applies_to` | 应用 → 被应用的概念 | CDN 回源 → 协商缓存 | 应用 |
| `contrast` | 双向 | 强缓存 ↔ 协商缓存 | 两端 |
| `related` | 双向，缺省值 | 其他 | 两端 |

- 单向关系的另一端在“被依赖 / 被引用”段落以普通文字列出来源概念，不加双链。
- 概念笔记“相关概念”按类型分组显示。
- 跨教材关系（两端概念来自不同教材）在笔记中单列“与其他教材的联系”，节点加标签 `learning/cross-curriculum`。
- 校验：`type` 取值受限；`prerequisite` 不允许形成环，成环时拒收并列出环。
- 一对概念之间只保存一条关系：后来的记录重新声明同一对概念（包括反方向）时替换原有类型、方向与备注；同一条记录内以第一次声明为准。
- 兜底：`session end` 仍要求每个本次涉及的概念要么有关系、要么列入 `no_related`；Skill 改为“只连真实存在的关系，拿不准就写 no_related，不要为结束学习凑关系”。
- `learn next` 暂不使用关系类型；先修关系留给 v0.2 课程排序使用。

## 数据与兼容性影响

- Interpretation Record 的 `related` 新增可选 `type`，缺省 `related`；旧记录回放结果不变。
- 已有关系全部视为 `related`，可由 Agent 用新记录补充类型（后一条覆盖前一条）。

## 验收条件

1. 五种类型都能提交并按方向渲染；非法类型与先修环被拒收。
2. 单向关系在图谱中只有一条从依赖方出发的边。
3. 跨教材关系出现在单独段落并带标签。
4. 旧 Vault 重建结果中关系部分与 v0.1.7 等价（全部为 related）。

## 决策

2026-09-28 接受，排入 v0.1.8。

2026-09-28 实现：关系类型与方向存于 Learner Model；一对概念只保存一条关系，后来的记录替换，同一记录内以首次声明为准；先修成环时拒收；跨教材关系单列并加标签。
