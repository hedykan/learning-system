# 变更摘要

把学习者的目标从一句原话变成结构化、有证据的“目标卡”：要达成什么、用在哪里、已有基础、时间与深度、怎样算学会、关注的具体场景。目标卡存在课程里，建课、排序、选资料和课程调整都参照它。

## 动机

v0.2 的目标只以一句话存进课程，Skill 只要求“问一两个问题”。v0.2 e2e 中 Agent 凭一段自我介绍就交出了大纲；学到什么程度、每周多少时间、具体用在什么场景都没问，也没有记录，之后也无法对照“还差什么”。

## 目标行为

- 目标卡字段，每项为 `{"text": "...", "evidence": [{"turn": "...", "quote": "..."}]}`，证据是学习者原话：

  | 字段 | 含义 | 必填 |
  | --- | --- | --- |
  | `outcome` | 学完要能做到什么 | ✓ |
  | `context` | 用在什么场景（工作、项目、考试） | |
  | `background` | 已有基础 | |
  | `constraints` | 时间、深度、偏好（如“每周 3 小时、偏实战”） | |
  | `success_criteria` | 怎样算学会 | |
  | `focus` | 具体关注点列表，每项另有 kebab-case `id`（如 `multi-tenancy`） | |

- 来源两种：摸底评估中的 `goal_card`（CR-2026-044），或 `learn curriculum goal set --file -`（证据对照当前 Session 的原始对话）。两者都校验证据确为学习者原话。
- `learn curriculum goal show [--json]`；每次修改保留旧版本（`Curriculum/<id>/goal-history/`）。
- 从目标建立的课程（CR-2026-040）在提交大纲前必须已有目标卡；跟随教材的课程可选。
- 教材首页顶部显示目标卡；学习首页“正在学习”显示 `outcome`。

## 数据与兼容性影响

新增 `Curriculum/<id>/goal.yaml`；旧课程没有目标卡，不受影响。旧的目标课程在下次提交大纲时才被要求补目标卡。

## 验收条件

1. 证据不是学习者原话时拒收；缺 `outcome` 时拒收。
2. 目标课程没有目标卡时提交大纲被拒，并说明先做目标访谈。
3. 修改目标卡后历史版本可查。

## 决策

2026-09-28 接受，排入 v0.2.1。
