# 变更摘要

新增 `learn curriculum outline review`：逐条列出草案的“为什么学”、先修、概念、证据提示、资料，以及它服务于目标卡的哪个关注点。程序检查目标卡里的每个关注点都至少有一个条目覆盖；目标课程在关注点全部覆盖、每个叶子条目都写了“为什么学”之前不能确认。

## 动机

学习者往往只回一句“可以”就确认了大纲，没有机会逐节修改；也没有办法发现“目标里提到的多租户，大纲里根本没有”。覆盖检查是确定性的，适合由程序做。

## 目标行为

- 大纲条目新增 `serves`：它服务的目标卡关注点 `id` 列表，必须存在于目标卡的 `focus` 中。
- `learn curriculum outline review [id] [--json]`：每个条目的 why、先修、概念、`serves`、证据提示（CR-2026-044）、已挂资料；末尾列出未被覆盖的关注点。草稿与已确认的大纲都可评审。
- 目标课程 `outline confirm` 的前置条件：有目标卡；每个叶子条目有 `why`；每个关注点至少被一个条目 `serves`。不满足时拒绝并列出缺项。
- Skill：确认前把评审结果讲给学习者（每节一句话的“为什么学”和资料），请学习者增删、改顺序；学习者改动后重新提交草案再评审。
- 教材首页显示每个条目服务的关注点。

## 验收条件

1. `serves` 指向不存在的关注点时拒收。
2. 有未覆盖的关注点或缺 `why` 的叶子条目时，目标课程无法确认，错误列出缺项。
3. `outline review --json` 包含每个条目的证据提示与资料。

## 决策

2026-09-28 接受，排入 v0.2.1。

2026-09-28 实现：条目 `serves`，提交时校验关注点存在；`learn curriculum outline review [--json]`（为什么学、先修、概念、服务的关注点、证据提示、资料、未覆盖关注点、likely_known、是否可确认）；目标课程确认需目标卡、叶子条目都有 why、关注点全覆盖。
