# 变更摘要

挂载资料时记录为什么选它、对应目标卡的哪个关注点；Skill 规定 Agent 用目标卡的场景和关注点构造搜索，并优先选择与学习者现有技术栈相符的资料。

## 动机

v0.2 e2e 中 Agent 挂了 5 份资料，但选择理由没有记录；学习者之后看不出“为什么这一节看 pgvector 文档而不是别的”。目标里的具体场景（如 Elasticsearch、多租户）也应该直接决定搜什么。

## 目标行为

- `learn source attach ... --why "<理由>"`（至多 120 字）与可选 `--serves <focus-id>`；记录在挂载上。
- 教材首页在条目的资料后显示理由；`outline review` 同样显示。
- Skill：
  - 搜索前先列出本节要回答的问题，结合目标卡的 `context` 与 `focus` 构造查询（例：学习者用 Elasticsearch → 优先 Elastic 官方文档的对应章节）；
  - 每个条目至少一份原始来源；挂载时写 `--why`；
  - 找不到合适来源时如实标注，而不是挂一份不相关的资料凑数。

## 验收条件

1. `--why` 超长被拒；`--serves` 指向不存在的关注点被拒。
2. 教材首页与评审输出显示理由。

## 决策

2026-09-28 接受，排入 v0.2.1。
