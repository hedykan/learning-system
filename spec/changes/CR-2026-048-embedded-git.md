# 变更摘要

学习库的提交、状态、历史查询与代码项目的按提交读取，改用纯 Go 的 go-git 实现，不再调用系统的 `git` 命令。行为保持不变。这是手机端（gomobile 编译，没有 `git` 可执行文件）与之后 `learn sync` 的前提。

## 动机

iOS 与 Android 上没有 `git` 命令；桌面上 `git` 也不一定安装、身份不一定配置（v0.1.8 首次发布时，CI 就因缺少 Git 身份失败）。

## 目标行为

- `gitx` 的全部操作（初始化、状态、未提交计数、提交、修正上一次提交、最近提交时间）由 go-git 实现，函数签名不变。
- 新仓库的默认分支为 `main`。
- 提交身份按顺序取：环境变量 `GIT_AUTHOR_*`、`GIT_COMMITTER_*`，学习库的仓库配置，用户全局 Git 配置，最后回退为 `Learning OS <learn@localhost>`。缺少身份不再导致提交失败。
- 遵守各级 `.gitignore`。
- 代码项目（CR-2026-030）按提交读取文件、检测提交与工作区状态也改用 go-git。
- 沙箱禁止写 `.git` 时，提交仍会失败，由 CR-2026-024 的提醒处理，行为不变。

## 数据与兼容性影响

仓库格式就是标准 Git，已有学习库不受影响，可继续用任何 Git 客户端操作。依赖新增 go-git v5.16.2（保持 Go 1.23）。

## 风险

- go-git 的工作区状态计算比命令行慢；学习库规模小，影响可忽略；代码项目的万文件性能验收继续适用。

## 验收条件

1. 现有测试在未改动断言的情况下全部通过。
2. 没有配置任何 Git 身份时，自动提交成功，作者为回退身份。
3. 在不含 `git` 命令的 PATH 下，初始化、学习、提交、代码项目读取全部可用。

## 决策

2026-09-29 接受，排入 v0.2.3。

2026-09-29 实现：`internal/gitx` 与代码项目读取改用 go-git v5.16.2，非测试代码中不再调用 `git` 命令；初始化时与命令行一致地创建 `.git/info/exclude`。go-git 不执行 Git 钩子，测试改用只读的 `.git/objects` 模拟沙箱中的提交失败。已验证：命令行 git 创建的学习库经 go-git 提交后 `git fsck` 通过，两者统计的未提交数一致。
