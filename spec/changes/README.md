# 需求变更流程

## 流程

1. 将尚不明确的想法先加入 `spec/ideas.md`。
2. 需要评估时，复制 `template.md` 创建 `CR-YYYY-NNN-<slug>.md`。
3. 写清动机、行为差异、数据兼容性、风险和验收条件。
4. 评审后标记为 `accepted`、`deferred` 或 `rejected`。
5. `accepted` 的变更必须更新对应版本基线和开发计划，再修改代码。
6. 实现与测试完成后标记 `implemented`，并链接相关文件或提交。

## 当前版本准入

当前版本只接受阻断发布的数据安全问题、验收缺口和无法向后兼容的早期纠正。新增命令、格式或自动化能力默认进入下一版本。
